Benchmarks

Three encrypted computations, one real machine, measured side by side

Three separate experiments, three separate walkthroughs. This page is the comparison: what each one actually cost, in bootstraps and wall-clock time, all measured on the same host (Apple M-series, 8 cores, macOS/arm64, OpenFHE built from source) at the same demo CKKS parameters (HEStd_NotSet, ring 213).

The three experiments

Approach E

Distance + threshold

Compares two already-known positions and decrypts only a count of violations. 7 real close-approach events, 63 candidate times, one batched computation.
Kepler

Closed-form propagation

Solves Kepler's equation under encryption to place a satellite at a query time, from private orbital elements. No pre-existing position needed.
RK4

General numerical propagation

The fallback for dynamics with no closed form: walks forward in small encrypted steps, re-evaluating the force at every one.

The benchmark

Bootstraps are the dominant cost driver under CKKS — each one is the single most expensive operation in any of these pipelines. Wall-clock time follows directly from how many a computation needs. Both are shown below, for all three experiments, plus RK4's own extrapolation to the step count that would actually match Kepler's accuracy.

Reading the gap honestly

These aren't quite the same unit of work — Approach E's 8.5s covers 7 events batched into one SIMD computation, Kepler's 3.86s covers 5 separate query times, RK4's 162s covers 4 sequential integration steps. What's directly comparable is the mechanism: all three are CKKS pipelines on the same host at the same parameters, and bootstrap count is what predicts wall-clock cost in every one of them. Kepler needing zero is a property of having a closed form to exploit; RK4 needing 4 per step is a property of not having one.

The RK4 "accurate" bar (720 bootstraps, ~2.5 hours) is extrapolated from the measured steady-state cost (4 bootstraps, ~50.0s/step) × the 180 steps 18_'s own error table says are needed to match Kepler's sub-meter floor. It was not run end to end — see the RK4 walkthrough for why that run wasn't attempted here.
Kepler's 0 bootstraps and Approach E's 3 both sit at real security parameters' mercy too: production (HEStd_128_classic) parameters need a far larger ring, and Approach E's own report measured that ring's key generation alone exceeding 24GB on a 16GB machine. None of the numbers on this page are production-security numbers — see each walkthrough's own honesty notes.
